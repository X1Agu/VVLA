# VVLA 首版代码交付要求

第三方从同一个版本安装 VVLA 后，应能在目标卡上用公开接口复现实测配方，并看清每次请求究竟走了哪条路径。`vvla` 分支从 `d8c9e95` 收编公共调度和客户端（`2d93ce5`）、OFT（`509e0f1` 含 `a3fa4b3`）及 LingBot（`ddcfc62`）。下文的默认行为与安装体验均是首版验收目标。

## 默认行为

| 用户场景 | 首版应交付的行为 |
| --- | --- |
| 单臂直接推理 | SDK 直连该模型的隔离 worker。B1 走经过验证的专用路径，无需启动网络服务或进入组批队列。 |
| 调用方已有整批观测 | SDK 按已支持的宽度直接执行真批。逐行保留请求 ID 和 seed，按原顺序交回独立持有的 CPU float32 动作。 |
| 多客户端分别提交 B1 | 本地异步接口和 HTTP/WebSocket 二进制服务共用默认 FIFO。批宽以模型实际执行为准。保留显式 EDF、Slack-FIFO、cohort Slack-EDF 及独立可选的 AsyncOmni 适配。 |

| 模型 | 默认与显式选项 |
| --- | --- |
| π0.5 H50 | G4 使用经验证的 Prefix FP8，批路径需要匹配的 cuBLASLt 策略表。A100 80 GB、RTX 4090 和 RTX 3090 使用各自实测的 BF16 路径。保留显式 BF16、参考路径与已有的 OpenPI H10 契约。 |
| OpenVLA-OFT | 单臂和在线服务均默认最终纯 BF16。按卡保留实测注意力后端和权重打包方式。G4、4090 可显式选择已测的 224 个语言投影混合 FP8 配方。 |
| LingBot-VLA2 | 专用 B1 和在线默认均走混合精度 cache32。在线 C8 可以交付八个客户端的请求，模型逐次执行 B1。固定布局 B4 有独立的 TrueBatch 入口。split-stage 为显式实验选项，G4 的配对闭环复现过新增失败。保留已有纯 BF16 等显式配方的语义。 |

G4 指本轮使用的 RTX PRO 6000 Blackwell Server Edition。每项默认配置应能追溯到具体显卡、checkpoint 和负载。启动时结合 GPU 架构、总显存、空闲显存、可用算子和配套资产选择路径。未实测组合标明验证范围。自动降档时返回原因，显式指定但无法执行的精度须清楚报错。

发布分支保留了在线配置、原始回执的归档标识和 SHA-256。π0.5 在 A100 的正式 FIFO 是 cap 4、等待 2 ms，两张消费卡是 cap 4、等待 0 ms。两张消费卡的 LingBot cache32 和 A100 的 split-stage 已更新到三个 60 秒的正式窗口。4090 的 OFT mixed FP8 对应同卡三方对照的 cap 4、等待 0 ms。G4 的 π0.5 策略表按正式运行使用的字节保存，使用时仍需通过本机兼容性检查。[在线配置](../src/vvla/data/online-profiles.json) · [24 组实测策略](../packages/pi05/src/vvla_pi05/lite/lt-tactics-pro6000.json)

## 发版怎么验

1. **能独立安装。** 官方 Linux x86_64、Python 3.12、PyTorch 2.13.0+cu130 / CUDA 13.0 栈提供容器和隔离环境安装入口。SDK 保持轻量，三个模型的依赖独立。用户可用本地资产或固定 revision 的 Hub 模型及配套资产启动。缺少权重、组件或访问权限时能定位到具体项。源码目录外用发布包装好后，能加载实际需要的原生扩展。
2. **能从公开入口使用和诊断。** SDK 和轻量网络客户端能完成推理，统一 CLI 提供 `doctor`、`serve` 和 `bench`。二进制请求保留输入与返回的所有权，取消、超时、过载和 worker 故障均有明确结果。版本、实际模型配方、注意力后端、真实批宽、回退、首次建图与重建、排队和执行耗时均可核验。
3. **动作与行数对得上。** B1 用同卡、同配方的冻结观测和种子复核动作，沿用各模型登记的执行前缀和夹爪门槛。支持真批的路径在 B2/B4 换序、替换一行和后续调用后检查动作归属及独立性。并发服务覆盖稀疏到达与满负载，核对真实请求数、模型执行行数和返回数。G4 的 OFT 实验适配器按本批行数调整图宽。首版整理函数在容量 4 时也须对单条输入执行真实 B1；动作与张量宽度须从公开服务核验。LingBot 串行默认单独按 B1 验收。[包内 OFT 行整理代码](../packages/oft/src/vvla_oft/service.py)
4. **性能在同一边界复核。** 同卡、同资产、同精度、同预热和同计时边界对照冻结版本。专用 B1、固定真批、独立 B1 客户端的 C8 分别测。新网络入口记录客户端端到端 P95 和吞吐，同时保留模型侧数据。以重复窗口判断回归，±3% 可作同口径复测提示。首次捕获与稳态重建分开，预热覆盖后的零重建按具体路径和负载检查。
5. **交付就绪有据可查。** 候选提交、各包版本及摘要、各 worker 依赖、checkpoint 与辅助资产可核对。自动化覆盖公共契约、原生资源打包及源码外导入。本机小模型验证执行机制。现有打包检查复用宿主 ML 依赖，全新依赖安装需单独验证。最终候选在干净目标卡上通过默认入口的 B1、适用的行级测试和 C8 后，记录该卡的验收状态，再标记正式版本。
